A first-time setup guide

Connect payments from database to Flutter

This page explains what to do, where to do it, and what you should see after each step. Start in test mode. Do not accept real payments until the test steps work.

There is only one API to deploy for customers

StoreManagement.Api is the website/server your Flutter app talks to. SubscriptionPlatform.Core is a code library used inside it. It is not a separate website or server. The separate SubscriptionPlatform.Api is only a temporary admin tool for creating the application and plan IDs.

Follow these steps in order

  1. Understand the parts
  2. Prepare accounts and hosting
  3. Create the databases
  4. Create the plan IDs
  5. Enter server settings
  6. Set up Razorpay Test Mode
  7. Publish the API
  8. Point Flutter to the API
  9. Try every step as a customer
  10. Switch to real payments
1

Understand the parts before changing settings

  • Flutter app: screens customers use on their phone. It asks the API to show plans and open Razorpay Checkout.
  • StoreManagement API: the server. It creates orders, checks payment results, and controls access.
  • SubscriptionPlatform.Core: a separate project folder with payment/subscription code. It is compiled into the StoreManagement API.
  • MySQL: stores store data and subscription/payment records. These are two databases, even if they are on one MySQL server.
  • Razorpay: takes the customer's payment and sends a signed message to the API when payment status changes.

The customer flow is: choose a plan in Flutter → API creates an order → Razorpay Checkout collects payment → Flutter sends the result to the API → API verifies it → the app gets subscription access.

What the current options meanFree trial does not charge the customer. Paid 3-month, 6-month, and 1-year options are one-time prepaid purchases. They do not renew automatically. The app does not create an automatic monthly/yearly Razorpay mandate.
2

Prepare the accounts and website address

Do this
  1. Sign in to Razorpay and finish the business/account activation steps it asks you to complete.
  2. Choose the public address customers will use for the API, such as https://api.example.com. It must have a working HTTPS certificate.
  3. Choose a MySQL host that your API server can reach privately. Do not make the database open to everyone on the internet.
  4. Make two environments: staging for safe practice and production for real customers. Each environment needs its own database credentials and Razorpay keys.
Ready to continue whenYou have the Razorpay account, an HTTPS staging API address, an HTTPS production API address, and a MySQL server for each environment (or clearly separated databases).

Razorpay may require business, bank, website, or other checks before it allows Live Mode. Follow the tasks shown for your account.

3

Create the two databases and tables

These commands are for a new installation. Run them from the StoreManagementApi solution folder. You need the MySQL command-line program installed, and the MySQL server must be running. When it asks for a password, type the MySQL administrator password.

3A. Create the StoreManagement database

mysql -u root -p < StoreManagement.Api/Scripts/schema.sql
mysql -u root -p store_management_db < StoreManagement.Api/Scripts/create_customer_credit_invoices.sql
mysql -u root -p store_management_db < StoreManagement.Api/Scripts/add_refresh_tokens.sql

The first file creates the database and main tables. The next two create the customer-credit and refresh-token tables used by the API.

Do not run every SQL file without checking first.Several files in StoreManagement.Api/Scripts are upgrades for older databases. The current schema.sql already has many of those columns. Running an old ALTER TABLE again can fail because the column already exists. If you already have data, back it up and ask your database administrator to check which upgrades are still needed. Never test migrations on the only copy of production data.

3B. Create the subscription database

mysql -u root -p < SubscriptionPlatform.Core/Migrations/001_initial.sql

This creates a separate database called SubscriptionDatabase and its plan, subscription, payment, and webhook tables. If you ran this current 001 file, do not run migration 002; both price columns are already included. File SubscriptionPlatform.Core/Migrations/002_fixed_term_prices.sql is only for an older database that is missing the columns. If you are not sure, check the columns before running an upgrade.

If you already saw “Duplicate column name”Do not delete the database or remove the columns. Connect to the database and check what is already there: 
mysql -u root -p SubscriptionDatabase
SHOW COLUMNS FROM plans LIKE 'three_month_amount_minor';
SHOW COLUMNS FROM plans LIKE 'six_month_amount_minor';
SHOW COLUMNS FROM customers LIKE 'email';
If both plan columns appear, they were created successfully. The email row should show type varchar(320) and Null as YES. If it does not, run this one statement inside the MySQL prompt, then check again: 
ALTER TABLE customers MODIFY COLUMN email VARCHAR(320) NULL;
Type exit to leave the MySQL prompt. No database reset is needed.

3C. Create a runtime database login

The API should not connect as MySQL's root user. Ask your database administrator to create a restricted user with read/write access to both databases. Example only; replace the username, host range, and password with values approved for your server:

CREATE USER 'store_api'@'10.%' IDENTIFIED BY '<unique-long-password>';
GRANT SELECT, INSERT, UPDATE, DELETE ON store_management_db.* TO 'store_api'@'10.%';
GRANT SELECT, INSERT, UPDATE, DELETE ON SubscriptionDatabase.* TO 'store_api'@'10.%';
FLUSH PRIVILEGES;

10.% is only an example network range. Your database administrator must limit access to the API server's actual network.

Ready to continue whenBoth databases and tables exist, and the API runtime user can connect to both without using the root account.
4

Create the application ID and plan ID

These two IDs tell StoreManagement which subscription plan belongs to it. Usually you do this once. The app key is only needed to administer the plan; customers never use it.

4A. Start the admin tool on your development computer

Open a terminal in the StoreManagementApi solution folder. Point it at the SubscriptionDatabase you created in Step 3. Create temporary, strong secrets for this local admin session. Do not use your production keys here.

export ConnectionStrings__SubscriptionDatabase='Server=<mysql-host>;Port=3306;Database=SubscriptionDatabase;User ID=store_api;Password=<password>;GuidFormat=Char36;'
export Authentication__SigningKey='<random-secret-at-least-32-bytes>'
export Authentication__BootstrapAdminKey='<random-admin-secret-at-least-32-characters>'
dotnet run --project ../SubscriptionPlatform.Api/SubscriptionPlatform.Api.csproj

Leave that terminal running. It prints a local address such as http://localhost:12345. Use the address it prints in the next commands. If you are using Windows PowerShell, set values with $env:ConnectionStrings__SubscriptionDatabase = "..." instead of export.

4B. Get the admin token

Open a second terminal. Replace the URL and secret with the values from the first terminal. This request proves that you are allowed to create an application.

curl -X POST 'http://localhost:<port>/api/v1/auth/token' \
  -H 'Content-Type: application/json' \
  -d '{"adminKey":"<your-bootstrap-admin-secret>"}'

The response contains access_token. Copy it temporarily; it is the admin bearer token used in the next request.

4C. Register StoreManagement

Replace <admin-token> with the token you just received:

curl -X POST 'http://localhost:<port>/api/v1/admin/applications' \
  -H 'Authorization: Bearer <admin-token>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"StoreManagement"}'

Copy the returned id and application_key into a secure temporary note. You need both for the next action. The key is only shown once; do not put it in the Flutter app.

4D. Get an application token and create your plan

Request a token using the application key:

curl -X POST 'http://localhost:<port>/api/v1/auth/token' \
  -H 'Content-Type: application/json' \
  -d '{"applicationKey":"<application-key>"}'

Use its access_token to create the plan. Replace the sample amounts with the prices you have decided to charge. Amounts use the smallest currency unit: 10000 is ₹100.00 for INR.

curl -X POST 'http://localhost:<port>/api/v1/plans' \
  -H 'Authorization: Bearer <application-token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "name":"StoreManagement Plan",
    "currency":"INR",
    "monthlyAmountMinor":0,
    "threeMonthAmountMinor":149700,
    "sixMonthAmountMinor":269700,
    "yearlyAmountMinor":479400,
    "trialDays":7,
    "featuresJson":"{}",
    "limitsJson":"{}"
  }'

The prices above are examples only. Change them to your real prices before using this plan. The response contains the plan id. Save that and the application id. These become the settings named SubscriptionPlatform__ApplicationId and SubscriptionPlatform__PlanId.

Ready to continue whenYou have saved the application ID and plan ID. Stop the admin tool by returning to its terminal and pressing Ctrl+C. It does not need to run while StoreManagement customers pay.
5

Enter the settings on the StoreManagement API server

Open your hosting provider's environment-variable or secrets page for the StoreManagement API. Add these names exactly. Put your own real values on the right-hand side.

ConnectionStrings__DefaultConnection=<connection to store_management_db>
ConnectionStrings__SubscriptionDatabase=<connection to SubscriptionDatabase>
SubscriptionPlatform__ApplicationId=<application ID from Step 4>
SubscriptionPlatform__PlanId=<plan ID from Step 4>
JwtSettings__SecretKey=<new random secret, at least 32 bytes>
Razorpay__KeyId=<test key ID for now>
Razorpay__KeySecret=<test key secret for now>
Razorpay__WebhookSecret=<test webhook secret for now>

A connection string is a one-line address plus login for one database. Example shape (do not copy the sample password):

Server=db.example.com;Port=3306;Database=store_management_db;User ID=store_api;Password=<password>;GuidFormat=Char36;SslMode=Required;

Use Database=SubscriptionDatabase in the second connection string. Set the same database host, account, and password if both databases share a server. Make sure the hosting provider saves variables for the correct app/environment, then restart the API after entering them.

Do not paste secret values in Flutter or this HTML file.Never commit database passwords, JWT secret, Razorpay Key Secret, Webhook Secret, or application key to Git. The Flutter app receives only the public Key ID and the order information needed to open checkout.
What a successful start looks likeThe API starts without a configuration error and can connect to both databases. If it says an ID is not a GUID, copy the full ID from Step 4. If it says a connection is missing, check the exact environment-variable spelling above.
6

Set up Razorpay Test Mode

Test Mode is a safe practice area. It does not take real money. Create test keys and a test webhook while still on the Razorpay dashboard's Test Mode.

  1. In the Razorpay dashboard, switch to Test Mode and open the API Keys area. Generate a Key ID and Key Secret.
  2. Put those values into the staging API's Razorpay__KeyId and Razorpay__KeySecret settings.
  3. Open the dashboard's Webhooks settings and add this URL, replacing the host with your staging API address:
    https://<staging-api-host>/api/subscription/webhook/razorpay
  4. Select the events payment.captured and payment.failed.
  5. Enter a webhook secret in Razorpay and save the webhook. Put that exact secret into the staging API's Razorpay__WebhookSecret setting, then restart the API.

The Key Secret and Webhook Secret are two different secrets. Razorpay uses the first for server API calls and the second to sign webhook messages. Check the official Razorpay dashboard/webhook instructions if the menu names have changed.

Ready to continue whenThe webhook is enabled and its URL is the StoreManagement API URL. Razorpay should show successful delivery after a test payment. Do not point it to the standalone admin API.
7

Build and publish the one API

On your development computer, open a terminal in the StoreManagementApi solution folder. Run:

dotnet restore StoreManagement.sln
dotnet build StoreManagement.sln --configuration Release
dotnet publish StoreManagement.Api/StoreManagement.Api.csproj --configuration Release --output ./publish

The publish command creates a publish folder. Upload the contents of that folder to the StoreManagement API app on your hosting provider. Set the secrets from Step 5 on that hosting app.

You are deploying only StoreManagement API. The subscription class library is included automatically in its published output because the API project references it. Do not start another website for SubscriptionPlatform.Core.

Ready to continue whenYour host says the StoreManagement API is running, the public HTTPS address opens, and the app can reach both MySQL databases. Razorpay documents test/live keys and capture requirements in its test and go-live guide.
8

Tell Flutter to use your StoreManagement API

This step is easy to miss. The Flutter project has a default API address. When you deploy to your own server, build a new app with your server's address. The address must end with /api. Do not use the SubscriptionPlatform admin address.

Android APK

From the solution folder, go into the sibling Flutter app and build a release APK:

cd ../StoreManagementApp
flutter pub get
flutter analyze
flutter build apk --release --dart-define=API_BASE_URL=https://<your-api-domain>/api

Replace <your-api-domain> with the real HTTPS domain. For example, if the API address is https://api.myshop.com, the value is https://api.myshop.com/api.

iPhone/iPad IPA

On a Mac with your Apple signing setup, use the same address:

flutter build ipa --release --dart-define=API_BASE_URL=https://<your-api-domain>/api

Install the release build on a real device and sign in. Flutter should load the subscription page from your StoreManagement API. The Key ID may be used by checkout. The Key Secret must never be included in the app.

Ready to continue whenThe installed phone app signs in against your deployed API and shows the options returned by the plan you made in Step 4.
9

Walk through the app like a customer

Keep the staging app configured with Razorpay Test Mode keys. Use only the test payment methods shown in your Razorpay account. Do not enter real card or bank details.

  1. Open Flutter and sign in with a test user.
  2. Open the subscription page. Check that it shows the right currency and prices.
  3. Tap the free trial. It should not open Razorpay. The app should show that trial access is active.
  4. Use another eligible test user to buy the 3-month term. Complete a successful test checkout. The app should wait for the server's verification before showing access.
  5. Repeat for the 6-month and 1-year options.
  6. Try a declined or cancelled test checkout. It should not unlock paid access, and the user should be able to try again.
  7. In the Razorpay dashboard, open the payment and make sure it is captured. An authorized-but-not-captured payment must not be treated as paid.
  8. Open the webhook delivery page. Check the test event reached /api/subscription/webhook/razorpay successfully.
  9. Close and reopen Flutter, sign in again, and confirm that the API still reports the correct access.
  10. Try a protected StoreManagement feature with a user who has no active subscription. The app should show the subscription screen.
If any check fails, stop here.Do not put live keys in the app to try to fix it. Check the API logs, database connection, application/plan IDs, key mode, webhook URL, and webhook secret while still in staging.
10

Change from test money to real payments

Only do this after Step 9 works and Razorpay has activated your account for Live Mode.

  1. In the Razorpay dashboard, switch to Live Mode. Generate live API keys. Do not reuse the test keys.
  2. In Live Mode, create a webhook to https://<production-api-domain>/api/subscription/webhook/razorpay. Select payment.captured and payment.failed.
  3. Make a new live webhook secret. Save it in the production StoreManagement API settings.
  4. Replace the production API's test Razorpay__KeyId, Razorpay__KeySecret, and Razorpay__WebhookSecret with the live values. Restart the API.
  5. Check the production app still has the correct production database, application ID, and plan ID.
  6. Build Flutter again with API_BASE_URL=https://<production-api-domain>/api and publish that signed release to your users.
  7. Watch the first payments in both the StoreManagement API logs and Razorpay dashboard. Confirm captured payments, webhook delivery, and settlement status.

See Razorpay's current Live Mode instructions and security checklist. Razorpay menu names and activation requirements may vary by account.
