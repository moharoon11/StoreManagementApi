StoreManagement · பணம் செலுத்துதல்

Flutter செயலியிலிருந்து பணம் பெறுவது வரை

ஒவ்வொரு படியிலும் என்ன செய்ய வேண்டும், எங்கே செய்ய வேண்டும், முடிந்ததும் என்ன பார்க்க வேண்டும் என்று எளிய தமிழில் விளக்கப்பட்டுள்ளது. முதலில் Test Mode-ல் முயற்சி செய்யுங்கள். எல்லா சோதனைகளும் சரியாகும் வரை உண்மையான பணம் பெறத் தொடங்க வேண்டாம்.

வாடிக்கையாளர்களுக்காக ஒரே ஒரு API-ஐ மட்டும் deploy செய்ய வேண்டும்

StoreManagement.Api தான் Flutter செயலி தொடர்பு கொள்ளும் server. SubscriptionPlatform.Core என்பது அந்த server பயன்படுத்தும் தனி code library; இது தனி server அல்ல. SubscriptionPlatform.Api என்ற மற்றொரு API-ஐ application ID மற்றும் plan ID உருவாக்க மட்டும் தற்காலிகமாகப் பயன்படுத்தலாம்.

இந்த வரிசையில் படிகளைச் செய்யுங்கள்

  1. இதில் உள்ள பகுதிகளைப் புரிந்துகொள்ளுங்கள்
  2. கணக்குகள் மற்றும் hosting தயார் செய்யுங்கள்
  3. இரண்டு database-களை உருவாக்குங்கள்
  4. Plan ID-களை உருவாக்குங்கள்
  5. Server அமைப்புகளை உள்ளிடுங்கள்
  6. Razorpay Test Mode அமைக்கவும்
  7. ஒரே API-ஐ publish செய்யவும்
  8. Flutter-ஐ API-க்கு இணைக்கவும்
  9. வாடிக்கையாளராக முழு flow-ஐ சோதிக்கவும்
  10. உண்மையான பணம் பெறத் தொடங்கவும்
1

அமைப்புகளை மாற்றுவதற்கு முன் இதைப் புரிந்துகொள்ளுங்கள்

  • Flutter செயலி: வாடிக்கையாளர் கைபேசியில் பயன்படுத்தும் திரைகள். Plan-களைப் பார்க்கவும் Razorpay Checkout திறக்கவும் இது API-யிடம் கேட்கும்.
  • StoreManagement API: server. இது payment order உருவாக்கும், payment சரியா என்று சரிபார்க்கும், யாருக்கு subscription access இருக்கிறது என்று முடிவு செய்யும்.
  • SubscriptionPlatform.Core: subscription/payment code இருக்கும் தனி project. இது StoreManagement API-க்குள் build ஆகும்.
  • MySQL: கடைத் தகவலும் subscription/payment தகவலும் சேமிக்கப்படும் database. ஒரே MySQL server-ல் இருந்தாலும் இவை இரண்டு database-கள்.
  • Razorpay: வாடிக்கையாளரிடமிருந்து பணம் பெற்று, payment நிலை மாறும்போது API-க்கு கையொப்பமிட்ட (signed) செய்தி அனுப்பும் service.

வாடிக்கையாளர் பயன்படுத்தும் வரிசை: Flutter-ல் plan தேர்வு → API order உருவாக்கும் → Razorpay-ல் payment → Flutter முடிவை API-க்கு அனுப்பும் → API சரிபார்க்கும் → சரியானால் செயலியில் access கிடைக்கும்.

இப்போதுள்ள payment option-கள் எப்படி வேலை செய்கின்றன?Free trial-க்கு பணம் வசூலிக்கப்படாது. 3 மாதம், 6 மாதம், 1 வருடம் ஆகியவை ஒவ்வொன்றும் ஒரு முறை முன்பணம் செலுத்தும் plan-கள். காலம் முடிந்ததும் வாடிக்கையாளர் மீண்டும் வாங்க வேண்டும். தானாக renew ஆகும் recurring payment இப்போது இல்லை.
2

Razorpay கணக்கும் இணைய முகவரியும் தயார் செய்யுங்கள்

செய்ய வேண்டியது
  1. Razorpay-ல் உள்நுழைந்து, உங்கள் கணக்கிற்கு கேட்கப்படும் வணிக விவரங்கள் மற்றும் activation படிகளை முடிக்கவும்.
  2. API-க்கு ஒரு பொதுவான இணைய முகவரியைத் தேர்ந்தெடுக்கவும். உதாரணம்: https://api.example.com. அந்த முகவரியில் HTTPS certificate வேலை செய்ய வேண்டும்.
  3. API server தனிப்பட்ட network வழியாக அணுகக்கூடிய MySQL server-ஐத் தேர்ந்தெடுக்கவும். Database-ஐ எல்லோரும் இணையத்தில் அணுகக்கூடியதாக வைக்க வேண்டாம்.
  4. இரண்டு சூழல்களை (environment) வைத்துக்கொள்ளுங்கள்: பாதுகாப்பான சோதனைக்காக staging, உண்மையான வாடிக்கையாளர்களுக்காக production. இரண்டுக்கும் தனித்த database login மற்றும் Razorpay key-கள் வேண்டும்.
அடுத்த படிக்குச் செல்லத் தயாராக இருக்கும் போதுRazorpay account, staging HTTPS முகவரி, production HTTPS முகவரி, மற்றும் API server-ல் இருந்து அணுகக்கூடிய MySQL server உங்களிடம் இருக்கும்.

Live Mode-ஐ அனுமதிப்பதற்கு முன் Razorpay வணிகம், வங்கி அல்லது website விவரங்களை கேட்கலாம். உங்கள் கணக்கில் காட்டப்படும் படிகளைப் பின்பற்றுங்கள்.

3

இரண்டு database-களையும் உருவாக்குங்கள்

கீழே உள்ள கட்டளைகள் புதிய அமைப்புக்கானவை. StoreManagementApi என்ற solution folder-ல் terminal திறந்து கட்டளைகளை இயக்குங்கள். MySQL இயங்கிக் கொண்டிருக்க வேண்டும்; mysql command-line tool கணினியில் நிறுவப்பட்டிருக்க வேண்டும். Password கேட்டால் MySQL நிர்வாகியின் password-ஐ உள்ளிடுங்கள்.

3A. StoreManagement database உருவாக்குங்கள்

mysql -u root -p < StoreManagement.Api/Scripts/schema.sql
mysql -u root -p store_management_db < StoreManagement.Api/Scripts/create_customer_credit_invoices.sql
mysql -u root -p store_management_db < StoreManagement.Api/Scripts/add_refresh_tokens.sql

முதல் file database மற்றும் முக்கிய அட்டவணைகளை உருவாக்கும். அடுத்த இரண்டு file-கள் customer credit மற்றும் refresh token அட்டவணைகளை உருவாக்கும்.

எல்லா SQL file-களையும் யோசிக்காமல் இயக்க வேண்டாம்.StoreManagement.Api/Scripts உள்ள சில file-கள் பழைய database-ஐ upgrade செய்ய மட்டும். தற்போதைய schema.sql-ல் அவற்றில் பல columns ஏற்கனவே உள்ளன. பழைய ALTER TABLE-ஐ மீண்டும் இயக்கினால் “column already exists” பிழை வரலாம். ஏற்கனவே data இருந்தால் முதலில் backup எடுத்து, எந்த மாற்றம் தேவையென்று database நிர்வாகியிடம் சரிபாருங்கள். Production data-வின் ஒரே பிரதியில் migration சோதனை செய்ய வேண்டாம்.

3B. Subscription database உருவாக்குங்கள்

mysql -u root -p < SubscriptionPlatform.Core/Migrations/001_initial.sql

இது SubscriptionDatabase என்ற தனி database மற்றும் plan, subscription, payment, webhook அட்டவணைகளை உருவாக்கும். தற்போதைய 001 file-ஐ இயக்கியிருந்தால், 002 migration-ஐ இயக்க வேண்டாம்; இரண்டு price columns-ம் 001-லேயே உள்ளன. பழைய schema-வில் அந்த columns இல்லாதபோது மட்டும் SubscriptionPlatform.Core/Migrations/002_fixed_term_prices.sql பயன்படுத்த வேண்டும். எந்த schema என்று தெரியாவிட்டால், முதலில் columns உள்ளனவா என்று சரிபாருங்கள்.

“Duplicate column name” பிழை ஏற்கனவே வந்திருந்தால்Database-ஐ delete செய்யவோ, columns-ஐ நீக்கவோ வேண்டாம். ஏற்கனவே உள்ள columns-ஐ முதலில் சரிபாருங்கள்: 
mysql -u root -p SubscriptionDatabase
SHOW COLUMNS FROM plans LIKE 'three_month_amount_minor';
SHOW COLUMNS FROM plans LIKE 'six_month_amount_minor';
SHOW COLUMNS FROM customers LIKE 'email';
இரண்டு plan column-களும் பட்டியலில் வந்தால் அவை database-ல் ஏற்கனவே உள்ளன. Email row-ல் type varchar(320) என்றும் Null மதிப்பு YES என்றும் இருக்க வேண்டும். அப்படி இல்லையென்றால், MySQL prompt-ல் இந்தக் கட்டளையை மட்டும் இயக்கி மீண்டும் சரிபாருங்கள்: 
ALTER TABLE customers MODIFY COLUMN email VARCHAR(320) NULL;
MySQL prompt-ஐ விட்டு வெளியேற exit என்று எழுதுங்கள். Database-ஐ மீண்டும் உருவாக்க வேண்டியதில்லை.

3C. API-க்காக தனி database login உருவாக்குங்கள்

API-ஐ MySQL root கணக்கில் இணைக்க வேண்டாம். Database நிர்வாகியிடம் இரண்டு database-களையும் படிக்கவும் மாற்றவும் மட்டும் அனுமதிக்கும் தனி user உருவாக்கச் சொல்லுங்கள். கீழே ஒரு உதாரணம்; username, network வரம்பு, password ஆகியவற்றை உங்கள் நிர்வாகி சரியான மதிப்புகளால் மாற்ற வேண்டும்:

CREATE USER 'store_api'@'10.%' IDENTIFIED BY '<unique-long-password>';
GRANT SELECT, INSERT, UPDATE, DELETE ON store_management_db.* TO 'store_api'@'10.%';
GRANT SELECT, INSERT, UPDATE, DELETE ON SubscriptionDatabase.* TO 'store_api'@'10.%';
FLUSH PRIVILEGES;

10.% என்பது உதாரணம் மட்டுமே. API server வரும் உண்மையான network-க்கு மட்டும் அனுமதி கொடுக்க வேண்டும்.

அடுத்த படிக்குத் தயாராக இருக்கும் போதுஇரண்டு database-களிலும் அட்டவணைகள் இருக்கும். API பயன்படுத்தும் தனி user இரண்டையும் அணுக முடியும்; root user-ஐ API பயன்படுத்தாது.
4

Application ID மற்றும் Plan ID உருவாக்குங்கள்

இந்த இரண்டு ID-கள் StoreManagement எந்த subscription plan-ஐப் பயன்படுத்த வேண்டும் என்று சொல்கின்றன. பொதுவாக இந்த அமைப்பை ஒரே முறை செய்தால் போதும். Application key-ஐ plan நிர்வாகத்திற்காக மட்டும் வைத்துக்கொள்ளுங்கள்; வாடிக்கையாளருக்குக் கொடுக்கக் கூடாது.

4A. உங்கள் development கணினியில் admin tool-ஐ இயக்குங்கள்

StoreManagementApi solution folder-ல் terminal திறக்கவும். Step 3-ல் உருவாக்கிய SubscriptionDatabase-ஐ connection string-ல் குறிப்பிடுங்கள். உள்ளூர் admin பயன்பாட்டிற்காக வலுவான தற்காலிக secret-களை அமைக்கவும். இங்கே production key-களைப் பயன்படுத்த வேண்டாம்.

export ConnectionStrings__SubscriptionDatabase='Server=<mysql-host>;Port=3306;Database=SubscriptionDatabase;User ID=store_api;Password=<password>;GuidFormat=Char36;'
export Authentication__SigningKey='<random-secret-at-least-32-bytes>'
export Authentication__BootstrapAdminKey='<random-admin-secret-at-least-32-characters>'
dotnet run --project ../SubscriptionPlatform.Api/SubscriptionPlatform.Api.csproj

இந்த terminal-ஐ திறந்தபடியே விடுங்கள். http://localhost:12345 போன்ற உள்ளூர் முகவரியை அது காட்டும். அடுத்த கட்டளைகளில் அந்த எண்ணைப் பயன்படுத்துங்கள். Windows PowerShell பயன்படுத்தினால் export என்பதற்குப் பதிலாக $env:ConnectionStrings__SubscriptionDatabase = "..." போன்ற முறையைப் பயன்படுத்துங்கள்.

4B. Admin token பெறுங்கள்

இரண்டாவது terminal திறக்கவும். முதல் terminal காட்டிய port எண்ணையும் நீங்கள் அமைத்த admin secret-ஐயும் கீழே மாற்றுங்கள். இந்த request மூலம் application உருவாக்க உங்களுக்கு அனுமதி இருப்பதை server சரிபார்க்கும்.

curl -X POST 'http://localhost:<port>/api/v1/auth/token' \
  -H 'Content-Type: application/json' \
  -d '{"adminKey":"<your-bootstrap-admin-secret>"}'

பதிலில் access_token வரும். அதை தற்காலிகமாக நகலெடுங்கள். அடுத்த படியில் அதுவே admin bearer token.

4C. StoreManagement application-ஐ பதிவு செய்யுங்கள்

<admin-token> இடத்தில் முந்தைய பதிலில் வந்த token-ஐ இடுங்கள்:

curl -X POST 'http://localhost:<port>/api/v1/admin/applications' \
  -H 'Authorization: Bearer <admin-token>' \
  -H 'Content-Type: application/json' \
  -d '{"name":"StoreManagement"}'

பதிலில் வரும் id மற்றும் application_key இரண்டையும் பாதுகாப்பான இடத்தில் சேமியுங்கள். Application key உருவாக்கும் போது ஒரு முறை மட்டுமே காட்டப்படும். அதை Flutter செயலியில் வைக்க வேண்டாம்.

4D. Application token பெற்று plan உருவாக்குங்கள்

Application key பயன்படுத்தி token பெறுங்கள்:

curl -X POST 'http://localhost:<port>/api/v1/auth/token' \
  -H 'Content-Type: application/json' \
  -d '{"applicationKey":"<application-key>"}'

இதில் வந்த access_token-ஐ வைத்து plan உருவாக்குங்கள். கீழே உள்ள விலைகள் உதாரணம் மட்டுமே. உங்கள் உண்மையான விலைகளை இடுங்கள். INR-ல் 10000 என்றால் ₹100.00.

curl -X POST 'http://localhost:<port>/api/v1/plans' \
  -H 'Authorization: Bearer <application-token>' \
  -H 'Content-Type: application/json' \
  -d '{
    "name":"StoreManagement Plan",
    "currency":"INR",
    "monthlyAmountMinor":0,
    "threeMonthAmountMinor":149700,
    "sixMonthAmountMinor":269700,
    "yearlyAmountMinor":479400,
    "trialDays":7,
    "featuresJson":"{}",
    "limitsJson":"{}"
  }'

இந்த sample விலைகளை உங்கள் வணிகம் முடிவு செய்த விலைகளால் மாற்றுங்கள். பதிலில் வரும் plan id-ஐயும் application id-ஐயும் சேமியுங்கள். Step 5-ல் அவற்றை அமைப்பீர்கள்.

அடுத்த படிக்குத் தயாராக இருக்கும் போதுApplication ID மற்றும் Plan ID பாதுகாப்பாக சேமிக்கப்பட்டிருக்கும். Admin tool இயங்கும் முதல் terminal-க்கு திரும்பி Ctrl+C அழுத்தி அதை நிறுத்துங்கள். வாடிக்கையாளர்கள் payment செய்யும்போது அந்த admin tool இயங்க வேண்டியதில்லை.

Endpoint request பற்றிய முழு விளக்கத்திற்கு admin API வழிகாட்டியை பார்க்கவும்.

5

StoreManagement API server-ல் அமைப்புகளை உள்ளிடுங்கள்

Hosting provider-ல் StoreManagement API-க்கான Environment Variables அல்லது Secrets பகுதியைத் திறக்கவும். கீழே உள்ள பெயர்களை அப்படியே சேர்த்து, வலப்புறத்தில் உங்கள் உண்மையான மதிப்புகளை இடுங்கள்.

ConnectionStrings__DefaultConnection=<store_management_db connection>
ConnectionStrings__SubscriptionDatabase=<SubscriptionDatabase connection>
SubscriptionPlatform__ApplicationId=<Step 4 application ID>
SubscriptionPlatform__PlanId=<Step 4 plan ID>
JwtSettings__SecretKey=<random secret, at least 32 bytes>
Razorpay__KeyId=<இப்போது test key ID>
Razorpay__KeySecret=<இப்போது test key secret>
Razorpay__WebhookSecret=<இப்போது test webhook secret>

Connection string என்பது database முகவரி மற்றும் login விவரங்கள் சேர்ந்த ஒரே வரி. அதன் வடிவம் இப்படியிருக்கும் (உதாரண password-ஐ அப்படியே பயன்படுத்த வேண்டாம்):

Server=db.example.com;Port=3306;Database=store_management_db;User ID=store_api;Password=<password>;GuidFormat=Char36;SslMode=Required;

இரண்டாவது connection string-ல் Database=SubscriptionDatabase என்று மாற்றுங்கள். இரண்டும் ஒரே MySQL server-ல் இருந்தால் server, user, password ஒன்றாக இருக்கலாம். Hosting provider-ல் சரியான environment-இல் சேமித்து, மதிப்புகளை மாற்றிய பிறகு API-ஐ restart செய்யுங்கள்.

Secret-களை Flutter-ல் அல்லது இந்த HTML file-ல் வைக்க வேண்டாம்.Database password, JWT secret, Razorpay Key Secret, Webhook Secret, application key ஆகியவை server-ல் மட்டுமே இருக்க வேண்டும். Flutter-க்கு public Key ID மற்றும் order விவரம் மட்டும் போகும்.
API சரியாகத் தொடங்கினால்Configuration பிழை இல்லாமல் API start ஆகி இரண்டு database-களையும் இணைக்க வேண்டும். ID GUID ஆக இருக்க வேண்டும் என்ற பிழை வந்தால் முழு ID-ஐ மீண்டும் நகலெடுங்கள். Connection இல்லை என்றால் மேலே உள்ள variable பெயர்களை எழுத்துக்கு எழுத்து சரிபாருங்கள்.
6

Razorpay Test Mode மற்றும் webhook அமைக்கவும்

Test Mode என்பது பயிற்சி செய்வதற்கான பாதுகாப்பான இடம்; இதில் உண்மையான பணம் பிடிக்கப்படாது. Razorpay dashboard-ல் Test Mode தேர்ந்தெடுத்தபடியே பின்வருவன செய்யுங்கள்.

  1. API Keys பகுதியைத் திறந்து test Key ID மற்றும் Key Secret உருவாக்குங்கள்.
  2. Key ID மற்றும் Key Secret-ஐ staging StoreManagement API-ன் Razorpay__KeyId மற்றும் Razorpay__KeySecret அமைப்புகளில் உள்ளிடுங்கள்.
  3. Webhooks பகுதியைத் திறந்து இந்த முகவரியைச் சேர்க்கவும். <staging-api-host> இடத்தில் உங்கள் staging முகவரியை இடுங்கள்:
    https://<staging-api-host>/api/subscription/webhook/razorpay
  4. payment.captured மற்றும் payment.failed நிகழ்வுகளைத் தேர்ந்தெடுக்கவும்.
  5. புதிய webhook secret ஒன்றை அமைத்து Razorpay-ல் சேமியுங்கள். அதே மதிப்பை staging API-ன் Razorpay__WebhookSecret-ல் உள்ளிட்டு API-ஐ restart செய்யுங்கள்.

Key Secret மற்றும் Webhook Secret வெவ்வேறு. ஒன்று Razorpay API-ஐ server அழைக்கப் பயன்படும்; மற்றொன்று webhook செய்தி Razorpay-இலிருந்து வந்ததா என்று சரிபார்க்கும். Dashboard மெனு மாறியிருந்தால் Razorpay அதிகாரப்பூர்வ வழிமுறைகளை பார்க்கவும்.

அடுத்த படிக்குத் தயாராக இருக்கும் போதுWebhook இயக்கப்பட்டு அதன் URL StoreManagement API-யைச் சுட்ட வேண்டும். Test payment செய்த பிறகு Razorpay-ல் delivery வெற்றியடைந்ததாகத் தெரிய வேண்டும். Admin API முகவரியை webhook-க்கு கொடுக்க வேண்டாம்.
7

ஒரே API-ஐ build செய்து publish செய்யுங்கள்

உங்கள் development கணினியில் StoreManagementApi solution folder-ல் terminal திறந்து இந்த கட்டளைகளை ஒன்றன் பின் ஒன்றாக இயக்குங்கள்:

dotnet restore StoreManagement.sln
dotnet build StoreManagement.sln --configuration Release
dotnet publish StoreManagement.Api/StoreManagement.Api.csproj --configuration Release --output ./publish

இந்த கட்டளைகள் publish என்ற folder உருவாக்கும். அந்த folder-க்குள் உள்ள கோப்புகளை hosting provider-ல் StoreManagement API app-க்கு upload செய்யுங்கள். Step 5-ல் வைத்த server secrets-ஐ hosting provider-லும் அமைக்கவும்.

Customer payment-க்காக StoreManagement API ஒன்றை மட்டுமே deploy செய்ய வேண்டும். Project reference காரணமாக SubscriptionPlatform.Core library அதன் output-ல் தானாக சேரும். Core-க்காக தனி website/server தொடங்க வேண்டாம்.

வெற்றிகரமாக முடிந்தது என்று தெரியும் அறிகுறிBuild பிழையின்றி முடிந்து, hosting provider API இயங்குகிறது என்று காட்டும். API இரண்டு database-களையும் அணுக வேண்டும். Razorpay-ன் test மற்றும் live payment வழிமுறைகளையும் பார்க்கவும்.
8

Flutter செயலியை StoreManagement API-க்கு இணைக்கவும்

இந்த படியை மறந்துவிடுவது எளிது. Flutter project-ல் இப்போது ஒரு default API முகவரி உள்ளது. உங்கள் server-ல் deploy செய்த பிறகு, உங்கள் API முகவரியுடன் புதிய release app build செய்ய வேண்டும். முகவரியின் முடிவில் /api இருக்க வேண்டும். SubscriptionPlatform admin முகவரியைப் பயன்படுத்த வேண்டாம்.

Android APK உருவாக்க

Solution folder-ல் இருந்து Flutter project-க்கு சென்று இந்தக் கட்டளைகளை இயக்குங்கள்:

cd ../StoreManagementApp
flutter pub get
flutter analyze
flutter build apk --release --dart-define=API_BASE_URL=https://<your-api-domain>/api

<your-api-domain> இடத்தில் உங்கள் உண்மையான HTTPS domain-ஐ இடுங்கள். உதாரணமாக API முகவரி https://api.myshop.com என்றால், முழு மதிப்பு https://api.myshop.com/api.

iPhone/iPad IPA உருவாக்க

Apple signing அமைப்பு உள்ள Mac-ல் இதே API முகவரியைப் பயன்படுத்துங்கள்:

flutter build ipa --release --dart-define=API_BASE_URL=https://<your-api-domain>/api

Release app-ஐ உங்கள் வழக்கமான Android/iOS store signing மூலம் sign செய்து, உண்மையான கைபேசியில் நிறுவிச் சோதியுங்கள். Checkout-க்கு public Key ID பயன்படலாம். Key Secret செயலிக்குள் ஒருபோதும் இருக்கக்கூடாது.

அடுத்த படிக்குத் தயாராக இருக்கும் போதுகைபேசியில் செயலியைத் திறந்து sign in செய்ய முடியும். Step 4-ல் உருவாக்கிய plan-ன் விலைகள் subscription திரையில் தெரியும்.
9

வாடிக்கையாளர் போல முழு payment flow-ஐ முயற்சி செய்யுங்கள்

Staging செயலி Test Mode key-களைப் பயன்படுத்துகிறதா என்று சரிபாருங்கள். Razorpay dashboard காட்டும் test payment முறைகளை மட்டும் பயன்படுத்துங்கள். உண்மையான card அல்லது bank விவரங்களைப் பயன்படுத்த வேண்டாம்.

  1. Flutter-ஐ திறந்து test user-ஆக sign in செய்யுங்கள்.
  2. Subscription திரையைத் திறந்து currency மற்றும் விலைகள் சரியா பார்க்கவும்.
  3. Free trial தொடங்குங்கள். Razorpay திறக்கக்கூடாது; செயலியில் trial access வந்திருக்க வேண்டும்.
  4. மற்றொரு தகுதியான test user-ஐப் பயன்படுத்தி 3 மாதத் திட்டத்திற்கு வெற்றிகரமான test payment செய்யுங்கள். Server சரிபார்த்த பிறகே access வருகிறதா பார்க்கவும்.
  5. 6 மாதம் மற்றும் 1 வருடத் திட்டங்களுக்கும் இதைச் செய்யுங்கள்.
  6. Declined அல்லது cancel செய்யப்பட்ட payment முயற்சி செய்யுங்கள். Access கிடைக்கக்கூடாது; மீண்டும் முயற்சி செய்ய முடிய வேண்டும்.
  7. Razorpay dashboard-ல் payment-ஐத் திறந்து அது captured ஆனதா பார்க்கவும். Authorized ஆனது மட்டும் போதாது.
  8. Webhook delivery பக்கத்தில் event /api/subscription/webhook/razorpay-க்கு வெற்றியாக வந்ததா பாருங்கள்.
  9. Flutter-ஐ மூடி மீண்டும் திறந்து sign in செய்யுங்கள். API சரியான subscription status-ஐத் தருகிறதா சரிபாருங்கள்.
  10. Subscription இல்லாத user-ஆக பாதுகாக்கப்பட்ட StoreManagement வசதியைத் திறக்க முயற்சி செய்யுங்கள். App subscription திரையைக் காட்ட வேண்டும்.
ஏதேனும் சோதனை தோல்வியடைந்தால் இங்கேயே நிறுத்துங்கள்.சரிசெய்ய Live key-களை Flutter-ல் போட வேண்டாம். Staging API log, database connection, application/plan ID, Test Mode, webhook URL, webhook secret ஆகியவற்றைச் சரிபாருங்கள்.
10

Test பணத்திலிருந்து உண்மையான payment-க்கு மாறுங்கள்

Step 9 சரியாக முடிந்ததும், Razorpay உங்கள் கணக்கிற்கு Live Mode அனுமதி கொடுத்த பிறகே இதைச் செய்யுங்கள்.

  1. Razorpay dashboard-ல் Live Mode தேர்ந்தெடுத்து புதிய live API key-களை உருவாக்குங்கள். Test key-களைப் பயன்படுத்த வேண்டாம்.
  2. Live Mode-ல் புதிய webhook உருவாக்கி https://<production-api-domain>/api/subscription/webhook/razorpay முகவரியை இடுங்கள். payment.captured மற்றும் payment.failed events-ஐத் தேர்ந்தெடுக்கவும்.
  3. புதிய Live webhook secret ஒன்றை உருவாக்குங்கள்.
  4. Production StoreManagement API-ன் secret manager-ல் live Key ID, Key Secret, Webhook Secret ஆகியவற்றை உள்ளிட்டு API-ஐ restart செய்யுங்கள்.
  5. Production API-ல் சரியான production database, application ID, plan ID உள்ளனவா சரிபாருங்கள்.
  6. API_BASE_URL=https://<production-api-domain>/api வைத்து Flutter-ஐ மீண்டும் build செய்து signed release-ஐ வாடிக்கையாளர்களுக்கு வெளியிடுங்கள்.
  7. முதல் சில payment-களின் போது API log மற்றும் Razorpay dashboard-ஐக் கவனியுங்கள். Payment captured ஆனதா, webhook வந்ததா, settlement நிலை என்ன என்று பாருங்கள்.

Razorpay-ன் Live Mode வழிமுறைகளையும் security checklist-ஐயும் பார்க்கவும். Dashboard மெனு மற்றும் account activation தேவைகள் கணக்குக்கு ஏற்ப மாறலாம்.

முக்கியமாக நினைவில் வையுங்கள்
